## 1. プロダクトの位置づけ

| 項目 | 合意内容 |
|------|----------|
| 主役 | **実行カレンダー**（いつ何をするかの配置・見直し）が画面の中心。あわせて **理念・目的・目標・プライムシート** をアプリ内から参照・追記できる **北極星バー** を置く（詳細は §2.1）。**年・月・週**の各スコープには **コメント** を付けられ、**そのスコープを表す数字（ラベル）** をクリックすると **詳細オーバーレイ** が開く（§2.2）。選択理論の5分類など **それ以外の長文設計** は引き続きツール外でもよい。 |
| 画面骨格 | **4ペイン**（左から **年 → 月 → 週 → 日**）。クリックでそのフェーズに応じた表示へ展開。四列の **上端（年ペインのさらに上）** に北極星バーを配置する。 |
| 実装の置き場 | **人生カレンダー専用の小さな新規アプリ**で MVP を検証。必要に応じて `workspace-ui-kit` へ部品移管。 |
| フロント土台 | **Next.js（App Router）**。 |

## 2. ナビゲーションとレイアウト

| 項目 | 合意内容 |
|------|----------|
| 選択モデル | **単一カーソル**（右の日／週の選択に合わせ、左の週・月・年が常に整合）。 |
| 年ペイン | **タイトル:** 中長期、年間行動計画。**2026年から**表示開始。**2026が一覧の上端**（起点）。**下へ行くほど未来**（2027, 2028…〜2032）。2025年以前は年ペインに出さない。 |
| 週 | **月曜始まり**。 |
| 狭い画面 | 幅が足りないときは **年／月／週／日をタブ等で切替**。広いときは **四列**。 |

### 2.1 北極星バー（理念・目的・目標・プライムシート）

**用語の整理:** 依頼文の「オスと画面」は、**ポップアップ／オーバーレイ**（親の四ペインの上に重なる画面）を指す想定で記載する。別の意図（例: 別タブでフルページ）なら差し替える。

| 項目 | 内容 |
|------|------|
| 配置 | **年ペインの上**（四列レイアウトでは **左端列の上** に **理念 / 目的 / 目標 / プライムシート** の **4ボタン** を横並び。**プライムシート** は **目標の右隣**。タブレイアウト時は **カレンダー領域の上** に同じ4ボタンを置くのが自然）。 |
| クリック時 | いずれかのボタン押下 → **オーバーレイ（モーダルまたは全幅ドロワー）** を開く。背後は四ペインを **半透明マスク** などで「ホスト画面」として残す。**プライムシート** も **理念・目的・目標と同じ遷移**（一覧＋新規＋編集が同型でよい）。 |
| オーバーレイ内 | **(A) 一覧**（既存項目のリスト）と **(B) 新規入力** への導線。 **「新規」** で **項目追加用フォーム**（別ステップまたは同一モーダル内の画面切替）を開く。 |
| 入力項目（MVP案） | 各カテゴリ共通で **タイトル必須**、**任意メモ**、**作成日時**（自動）。必要なら後から「有効期間」「並び順」を追加。プライムシート用に **固定フォーマット**（表形式テンプレ）を後から足す余地を残す。 |
| 永続化 | 予定と同様 **ブラウザ内**（別キーまたは JSON の別セクション）。バックアップ JSON に **理念／目的／目標／プライムシートの配列**を含めるかは実装時に決定。 |

### 2.2 年・月・週ペインのコメントと「数字クリック」詳細

**日ペイン**は予定（イベント）が主役のため、本節の **コメント＋数字クリック詳細** の対象は **年・月・週の三ペイン** とする（日の「その日だけのメモ」が要る場合は §6 にて拡張検討）。

| 項目 | 内容 |
|------|------|
| コメント | **年・月・週それぞれ**について、**現在単一カーソルで選ばれているスコープ**に紐づく **コメント（長文テキスト可・任意）** を保持する。各ペイン内には **抜粋1行** または **アイコン** で「コメントあり」を示す（実装時に決定）。 |
| 数字クリック | 各ペインで **そのスコープを識別する主ラベル（数字）** をクリックしたとき、**そのスコープ専用の詳細オーバーレイ** を開く。例: **年**は `2026` のような **年号**、**月**は `2026年3月` のような **年月表示の数字部分**、**週**は **週番号** または **月日範囲**のうち **主たるクリック領域として定義する一続きのラベル**（実装時に定義）。 |
| オーバーレイ内 | **スコープの見出し**（どの年／月／週か）を表示し、**コメント全文の編集**、**保存／閉じる**。必要なら **そのスコープに紐づく目標リンク**などは後続。 |
| 単一カーソルとの関係 | **数字クリック**は **詳細を開く**。**行やセルの他領域クリック**は **単一カーソルの移動**のみ、と **役割分担**するのがよい（同一クリックで両方起きると混乱）。詳細は §6。 |
| 永続化 | キー例: `year:2026` / `month:2026-03` / `week:2026-W11`（**週キー形式は未決**）。予定データと別オブジェクトでも同一 JSON 内でも可。 |

## 3. 日ペイン

| 項目 | 合意内容 |
|------|----------|
| 構成 | **上: 終日行**、**下: 24時間タイムライン**。 |
| 新規作成 | **終日行クリック → 終日予定**。**タイムラインクリック → 時刻付き**（開始はクリック位置、**既定の長さは常に60分**）。 |
| 時間の重なり | **横並びで幅分割**、多すぎる場合は **「+N」**。 |
| 初期スクロール | 表示中の日が **今日**のときだけ、表示直後に **現在時刻付近へ自動スクロール**。 |
| ドラッグ | MVP では **移動・リサイズともに行わない**（作成はクリック、変更はモーダル）。 |

## 4. データと永続化

| 項目 | 合意内容 |
|------|----------|
| 正本（MVP） | **ブラウザ内**（例: `localStorage` 想定）。 |
| バックアップ | **JSON の書き出し／読み込み**。 |
| インポート | **ID ベース upsert**（同一 ID は更新、無ければ追加。ID 無しは新規 UUID として取り込む）。 |
| タイムゾーン（MVP） | **ブラウザのローカル TZ のみ**。 |
| 繰り返し（MVP） | **単発のみ**（繰り返しルールは入れない）。 |
| スコープコメント | **年・月・週**キーごとに **コメント文字列**（任意）を保存。インポート時のマージ方針は **スコープキー一致で上書き** を既定案とする（要検討）。 |
| 北極星4カテゴリ | **理念／目的／目標／プライムシート** はいずれも **項目の配列**（各項目に id 等）として保存する案。 |

| 項目 | 合意内容 |
|------|----------|
| 追加・編集 UI | **中央モーダル**。 |

## 6. 未決・実装時に詰めるとよいこと

- **日付ライブラリ**（例: `date-fns` 採用など）の最終決定。
- **リポジトリ名・パス**の確定（本メモは `life-schedule` 配下に置いている）。
- **JSON ファイル形式**の詳細（ルートオブジェクト、予定配列のキー名、バージョン番号の要否）。
- **キーボードショートカット**、印刷・共有の要否。
- タブレイアウト時の **状態遷移**の細部（ワイヤー推奨）。
- 理念／目的／目標／プライムシートは **各1件だけ有効** にするか、**履歴として複数** 残すか（一覧の並び・「現在有効」の印）。
- 北極星オーバーレイは **中央モーダル** に統一するか、**ワイドドロワー** にするか（長文を書くならドロワー寄り）。スコープコメント編集は **長文になりやすい**ため **ドロワー推奨**の余地あり。
- 「オスと画面」が **ポップアップ以外**（別 URL・別ウィンドウ）の意図だった場合の差し替え。
- **週ペインのクリック対象**を **ISO週番号**にするか **「3/4–3/10」形式の範囲**にするか（キー設計とアクセシビリティに直結）。
- **行クリック（カーソル移動）**と**数字クリック（詳細オープン）**のヒット領域をどう分離するか（ラベルをリンク色にする／行は余白クリックで選択、等）。
- **日単位のスコープコメント**が後から必要になるか（現状は年・月・週のみ）。
